# Project Development

Этот файл нужен как журнал разработки проекта. Здесь фиксируем, что было сделано, зачем это нужно и что важно понять для защиты.

## Шаг 1. Изучили требования проекта

Что сделали:
- прочитали задание из PDF;
- выделили обязательные технологии: Java, Maven, MySQL, Servlet API, JSP, HTML, CSS;
- выписали обязательные сущности: `users`, `categories`, `products`, `cart`, `orders`, `order_items`;
- определили основной пользовательский сценарий: каталог -> корзина -> заказ -> история заказов.

Зачем:
- чтобы проект точно соответствовал критериям проверки;
- чтобы не добавлять лишний функционал, которого нет в задании.

Что важно понять:
- проверяется не сложный дизайн, а работающее веб-приложение;
- главная цель - показать понимание MVC, базы данных и HTTP-запросов.

## Шаг 2. Создали структуру Maven Web Project

Что сделали:
- добавили `pom.xml`;
- настроили сборку WAR-файла;
- добавили зависимости для Servlet API, JSP API, JSTL, MySQL Connector и BCrypt;
- создали стандартную структуру `src/main/java` и `src/main/webapp`.

Зачем:
- Maven управляет зависимостями и сборкой проекта;
- WAR-файл нужен для запуска приложения в Apache Tomcat.

Что важно понять:
- `pom.xml` описывает, из чего состоит проект и как его собирать;
- `target/online-shop.war` - итоговый файл для деплоя в Tomcat.

## Шаг 3. Реализовали MVC-архитектуру

Что сделали:
- создали `beans` для моделей данных;
- создали `dao` для работы с MySQL;
- создали `servlets` для обработки HTTP-запросов;
- создали JSP-страницы для интерфейса.

Зачем:
- MVC разделяет ответственность между слоями приложения;
- так код проще объяснять, поддерживать и проверять.

Что важно понять:
- Bean хранит данные;
- DAO выполняет SQL-запросы;
- Servlet управляет пользовательским запросом;
- JSP показывает результат пользователю.

## Шаг 4. Добавили базу данных MySQL

Что сделали:
- создали `database/init.sql`;
- добавили таблицы `users`, `categories`, `products`, `cart`, `orders`, `order_items`;
- настроили связи между таблицами через foreign key;
- добавили тестовые категории и товары.

Зачем:
- приложение должно хранить пользователей, товары, корзину и заказы в базе данных;
- тестовые данные позволяют сразу проверить каталог после запуска.

Что важно понять:
- корзина связана с пользователем и товаром;
- заказ связан с пользователем;
- позиции заказа связывают заказ с товарами и фиксируют цену на момент покупки.

## Шаг 5. Реализовали пользовательские сценарии

Что сделали:
- регистрация пользователя;
- вход и выход;
- просмотр каталога товаров;
- фильтрация по категориям;
- просмотр карточки товара;
- добавление товара в корзину;
- удаление товара из корзины;
- оформление заказа;
- просмотр истории заказов.

Зачем:
- это полный набор функций из технического задания.

Что важно понять:
- закрытые страницы проверяют наличие пользователя в сессии;
- после входа пользователь сохраняется в `HttpSession`;
- без входа нельзя работать с корзиной и заказами.

## Шаг 6. Добавили безопасность базового уровня

Что сделали:
- пароли хэшируются через BCrypt;
- SQL-запросы выполняются через `PreparedStatement`;
- оформление заказа выполняется через транзакцию.

Зачем:
- пароль нельзя хранить в открытом виде;
- `PreparedStatement` снижает риск SQL-инъекций;
- транзакция помогает сохранить заказ и товары заказа как единую операцию.

Что важно понять:
- BCrypt хранит не исходный пароль, а хэш;
- транзакция нужна, чтобы не получить заказ без позиций или позиции без заказа.

## Шаг 7. Добавили Maven Wrapper

Что сделали:
- создали ветку `feature/add_maven`;
- добавили `mvnw`, `mvnw.cmd` и `.mvn/wrapper`;
- обновили README: теперь проект можно собирать через `./mvnw clean package`;
- проверили сборку проекта.

Зачем:
- раньше глобальная команда `mvn` не была установлена;
- Maven Wrapper позволяет собрать проект без отдельной установки Maven.

Что важно понять:
- на macOS/Linux используется `./mvnw clean package`;
- на Windows используется `mvnw.cmd clean package`;
- wrapper сам скачивает нужную версию Maven.

## Шаг 8. Проверили сборку

Что сделали:
- запустили `./mvnw clean package`;
- Maven скомпилировал 22 Java-файла;
- был создан WAR-файл `target/online-shop.war`;
- сборка завершилась сообщением `BUILD SUCCESS`.

Зачем:
- это подтверждает, что проект компилируется и готов к запуску в Tomcat.

Что важно понять:
- успешная сборка не заменяет ручной тест в браузере;
- после сборки нужно проверить сценарий: регистрация -> вход -> каталог -> корзина -> заказ -> история.

## Шаг 9. Подготовили локальный запуск через Maven

Что сделали:
- создали ветку `feature/manual-testing-fixes`;
- проверили, что `localhost:8080` не отвечает, потому что Tomcat не был запущен;
- добавили Maven Cargo plugin для запуска встроенного Tomcat;
- добавили команду `./mvnw cargo:run` в README.

Зачем:
- теперь проект можно запустить из репозитория без ручного копирования WAR в отдельный Tomcat;
- это упрощает ручную проверку в браузере.

Что важно понять:
- `./mvnw clean package` только собирает WAR-файл;
- `./mvnw cargo:run` запускает приложение на `http://localhost:8080/online-shop/products`;
- полный сценарий магазина требует запущенный MySQL и применённый `database/init.sql`.

## Шаг 10. Подготовили MySQL через Docker

Что сделали:
- проверили, что на машине нет команды `mysql`;
- проверили, что Docker и Docker Compose доступны;
- добавили `docker-compose.yml` с MySQL 8;
- подключили `database/init.sql` как init-скрипт контейнера.

Зачем:
- так базу можно поднять без отдельной установки MySQL;
- это упрощает полный браузерный сценарий: товары, корзина, заказ, история.

Что важно понять:
- команда `docker compose up -d mysql` создаёт контейнер с MySQL;
- пароль root в учебной конфигурации: `password`;
- init-скрипт выполняется при первом создании данных контейнера.

## Шаг 11. Проверили полный пользовательский сценарий

Что сделали:
- запустили встроенный Tomcat через `./mvnw cargo:run`;
- подняли MySQL через `docker compose up -d mysql`;
- обнаружили проблему с кодировкой русских тестовых данных;
- добавили `SET NAMES utf8mb4` в `database/init.sql`;
- пересоздали тестовую базу в Docker;
- проверили сценарий в браузере.

Что проверили:
- каталог товаров открывается;
- категории и товары отображаются на русском языке;
- фильтр по категории работает;
- карточка товара открывается;
- регистрация тестового пользователя работает;
- вход в аккаунт работает;
- товар добавляется в корзину;
- товар удаляется из корзины;
- заказ оформляется;
- история заказов отображается;
- выход из аккаунта возвращает пользователя на страницу входа.

Зачем:
- это подтверждает, что проект не только собирается, но и проходит основной сценарий проверки преподавателем.

Что важно понять:
- если в базе появляются символы вида `Ð...`, проблема обычно связана с кодировкой при импорте SQL;
- для MySQL с русскими данными важно использовать `utf8mb4`;
- после изменения init-скрипта Docker volume нужно пересоздать, иначе старые данные останутся в базе.
